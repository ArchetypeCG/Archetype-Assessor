# Replace fictional practice learners with a WBL tracker

The application cannot read a workbook from this coding workspace into a separate live Render database. The authorised master user imports it through the authenticated website after deploying the update. No workbook, private row values or personal data is embedded in source code or published to GitHub.

1. Sign in as master user, open **Apprentices**, then **Import spreadsheet**.
2. Select the original WBL tracker XLSX. The importer finds the Pro Ref No / Apprenticeship Title header row below the title and legend, reads the first worksheet and previews the records. The uploaded workbook has 84 records and no first/last names, so reference-based labels are used. Six rows share a source reference; row suffixes keep these entries separate. Names can be added later when available.
3. Review the counts, references and programme matches. Choose **Validate & import** to import all validated rows and remove fictional practice learners in one transaction. A failed import leaves the database unchanged. Existing real learners are updated by reference only when their programme matches; other existing learners and accounts are retained. Repeating the same file updates the same records.

Only relevant source fields are retained: identifiers and names if supplied, programme/level, employer, start/end dates, assessor/IQA labels, functional-skills results, reported progress/target, risk and ELI dates, relevant progress notes and EPA outcome fields. Funding/DAS, awarding-body registrations, document administration and other unrelated tracker columns are discarded. Source notes and retained tracker detail are staff-only, enforced in the API for apprentice and employer accounts.

Known course variants such as NO DIPLOMA and Team Leader/Supervisor are matched by normalised course name and level. A course without a KSB schedule is created as a clearly marked empty schedule; the tracker supplies no criterion wording, so the import does not invent criteria. Staff names match only active existing accounts with the correct role. Missing/unmatched staff remain unassigned for the master user to assign. No emails, shared passwords or staff/learner login accounts are invented. Historical dates and text without valid dates are preserved as appropriate source fields; a tracker end date does not falsely mark a learner complete or gateway-ready.

Spreadsheet progress is displayed as **Tracker progress** on the learner overview, separately from verified portfolio coverage. No evidence, assessment decisions, hours or signatures are manufactured from a percentage. Source target percentages are retained; the live progress target is bounded to 0–100. Missing OTJ targets remain unset (0), not a fabricated programme requirement. Existing account passwords, standard IDs and actual learner work are preserved.

Fictional cleanup removes only learners explicitly flagged fictional and their linked evidence, hours, reviews, tasks, sessions, learning plans, IQA records and messages. Private files linked to those removed records are deleted in the same database transaction; actual learner files are retained. Accounts are retained, with any link to a removed fictional learner cleared. Normal startup no longer creates practice learners.

Retain a recent encrypted backup before importing, particularly if genuine work has been added to a practice learner. Backups remain subject to the existing retention and encryption rules. Original uploaded tracker files are not stored by this import path; relevant fields live in the existing persistent SQLite database.
